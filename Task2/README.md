# Процесс использует:
- отдельные пулы **VitaStore Onboarding**, **Legacy Store**, **AI SKU Matching Service**, **SAP ERP**;
- user task для обработки только спорных SKU;
- автоматическое сопоставление и контроль качества;
- повторное сопоставление исправленных данных;
- загрузку в SAP и публикацию каталога в Cloud POS;
- message flows между системами.


# 1. Логика To-Be процесса

## Основной happy path

1. M&A регистрирует приобретённый магазин.
2. Onboarding Platform формирует запрос на выгрузку каталога.
3. Migration Portal выбирает коннектор к legacy-кассе и автоматически извлекает данные.
4. Файл проходит:
   - антивирусную проверку;
   - проверку схемы;
   - проверку обязательных полей;
   - нормализацию текста, брендов, объёма и единиц измерения.
5. AI Service получает нормализованный каталог и эталон VitaStore.
6. Для каждой позиции AI возвращает:
   - исходный SKU;
   - предложенный VitaStore SKU ID;
   - confidence score;
   - признаки, повлиявшие на решение;
   - альтернативных кандидатов;
   - предупреждения о риске.
7. DMN-правила разделяют результаты на автоматические и требующие проверки.
8. Товаровед получает только исключения.
9. После проверки выполняются детерминированные проверки качества.
10. Mapping загружается в SAP.
11. SAP создаёт версию каталога магазина.
12. Каталог публикуется в Cloud POS.
13. Автоматические smoke-тесты проверяют штрихкоды, цены и продажи.
14. Менеджер подтверждает Go-Live.

# 2. Точка верификации человеком

## Предлагаемая политика

| Результат | Условие | Действие |
|---|---|---|
| Автоматическое принятие | Confidence ≥ 95%, есть валидный уникальный штрихкод, совпадают бренд, объём и единица измерения | Сопоставление принимается автоматически |
| Автопринятие с выборочным аудитом | Confidence ≥ 95%, но совпадение основано не только на штрихкоде | Принимается; 5% таких позиций отправляется на выборочную проверку |
| Проверка товароведом | Confidence 80–94,99% | User task со сравнением top-3 кандидатов |
| Обязательная ручная проверка | Confidence < 80% | Товаровед выбирает SKU, создаёт новый товар или отклоняет позицию |
| Независимая проверка | Дорогой товар, значительное расхождение цены, конфликт штрихкода или несколько SKU с одним barcode | Второе подтверждение старшим товароведом |
| Автоматический запрет | Несовместимые единицы измерения, бренд, категория либо критичные атрибуты | Сопоставление не проходит в SAP |

Порог `95%` должен быть реализован в DMN, а не зашит в worker. Это позволяет менять политику без повторного развёртывания процесса.

## Форма товароведа

Для каждой спорной позиции следует показывать:

- исходное название;
- нормализованное название;
- старую цену;
- штрихкод;
- бренд, объём, единицу измерения;
- трёх лучших кандидатов VitaStore;
- confidence каждого кандидата;
- различия атрибутов;
- историю ранее подтверждённых соответствий;
- действия:
  - подтвердить;
  - выбрать другого кандидата;
  - создать новый SKU;
  - отправить на вторую проверку;
  - исключить из миграции.

Решение товароведа записывается в audit log и используется как размеченный пример для дальнейшего улучшения модели.

# 3. Контроли снижения ошибок

1. **Barcode exact match имеет приоритет**, но только после проверки контрольной цифры и уникальности.
2. **Запрет на matching только по названию** для высокорисковых товаров.
3. Сравнение:
   - бренда;
   - категории;
   - объёма и размерности;
   - формы выпуска;
   - упаковки;
   - производителя;
   - ценового диапазона.
4. Проверка, что один внешний SKU не связан с несколькими внутренними SKU без явного правила.
5. Проверка аномального расхождения цены.
6. Выборочный аудит части автоматически принятых результатов.
7. Версионирование модели, справочника и набора правил.
8. Полный журнал:
   - входные данные;
   - версия модели;
   - confidence;
   - решение человека;
   - итоговый SAP ID.
9. Возможность отката версии каталога.
10. Smoke-тесты до Go-Live:
    - сканирование контрольной выборки штрихкодов;
    - проверка цены и промо;
    - тестовая продажа и возврат;
    - проверка фискализации;
    - проверка публикации каталога в Cloud POS.
