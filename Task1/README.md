# При распределении возможностей используются два критерия:

## 1. Стратегическая ценность

__Commodity__ — стандартная функция, не создающая конкурентного преимущества; предпочтительно покупать как SaaS.

__Differentiator__ — функция, формирующая конкурентное преимущество; целесообразно сохранять контроль над продуктом и развивать самостоятельно.

## 2. Требования к размещению

__SaaS / Buy__ — готовое облачное решение.

__PaaS/IaaS / Migrate or Build in Cloud__ — собственное решение на управляемой облачной платформе.

__In-house / On-Premise__ — только функции, которые нельзя перенести из-за требований законодательства, безопасности, задержек или аппаратных зависимостей.

## Легенда Heatmap

🔴 — дорогая, проблемная или избыточно кастомизированная commodity-возможность.

🟢 — конкурентный дифференциатор VitaStore.

🟠 — важная поддерживающая возможность, требующая стандартизации или модернизации.

⚪ — базовая возможность без критической проблемы.

# Главные дублирования и дорогие зоны
## Дублирование между магазином и HQ
| Возможность |	Магазин	| HQ | Проблема |
|-------------|---------|----|----------|
|Товарный справочник |	Local DB | SAP | Несколько версий данных, ночная синхронизация |
| Цены	| Локальная копия |	SAP	| Устаревание, FTP/XML-пакеты |
| Остатки |	Локальная БД | SAP/Smart Fulfillment | Несогласованность для Click & Collect |
| Лояльность | Тетрадка/касса |	SAP |	Нет единого баланса клиента |
| Премии сотрудников | Локальный расчёт	| HR/ERP | Разные правила и ручная сверка |
| Приём товара | Локальная система | SAP | Дублирование документов и остатков |
| Платёжная интеграция | Драйвер в POS | Центрального шлюза нет | Новое оборудование требует разработки|
| ИТ-инфраструктура |	Сервер и БД в каждом магазине |	Центральные системы	| 500 отдельных точек администрирования |

## Основные источники TCO
1. Локальные серверы, диски и запасные системные блоки.
2. Лицензии Windows Server и SQL на магазин.
3. Ручное администрирование и обновления.
4. Выезды ИТ-инженеров.
5. Поддержка нескольких типов POS и драйверов.
6. Ночные FTP/XML-интеграции.
7. Ручной SKU matching.
8. Простои при отказе локального оборудования.
9. Пересборка POS при подключении нового терминала.
10. Реактивная поддержка вместо централизованного мониторинга.
